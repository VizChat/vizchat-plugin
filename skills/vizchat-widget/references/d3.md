# d3 charts

A d3 widget is one way to write an inline widget: a plain-class renderer (extending `D3BaseRenderer` from
`@vizchat/widget-sdk/d3`) draws SVG in `renderContent(snapshot, context)`, and the View only hands it the snapshot. Everything
below is the recommended way; when you need special behavior, use the lower-level interface in parentheses directly.

## View: `d3View` (lower level: `useWidgetRenderer`)

```ts
// src/View.tsx
import { d3View } from '@vizchat/widget-sdk/react';
import { MyChartRenderer } from './lib/my-chart-renderer';
import definition from './definition';

export const View = d3View(definition, MyChartRenderer, {
  testId: 'my-chart',
  // Screen-reader alternative: a one-sentence summary + a data table with one row per item (translations in the viewState section)
  describe: ({ content }, t) => ({
    label: t('chartSummary', { count: content.items.length }),
    dataTable: {
      columns: [t('labelColumn'), t('valueColumn')],
      rows: content.items.map((item) => [item.label, item.value]),
    },
  }),
});
```

- It keeps the snapshot reference stable for you (building a new `{ content, config }` on every render makes the renderer
  redraw everything and get caught in a resize loop), measures the container, and hands the `viewState` translations to the
  renderer as `context.t`. `testId` writes `<testId>-view` / `<testId>-svg` on the shell and the svg.
- `describe` (required) computes the screen-reader alternative from the snapshot: the svg gets `role="img"` + `aria-label`, plus a visually hidden data table. `t` is the same as the renderer's `context.t`
  (the `viewState` section). When there is no data to tabulate, return only `{ label }`. See "Screen-reader alternative" in the conventions reference.
- The shell fills its parent with `minHeight: 150` by default: override it with `className` / `style`; use
  `overlay: ({ dimensions }) => …` to lay React content over the svg.
- When you need renderer callbacks, `onRendererInit` or a different shell, use
  `useWidgetRenderer({ RendererClass, snapshot, context })` directly, which returns `{ parentRef, svgRef, dimensions }` — then
  you `useMemo` the `snapshot` and `context` yourself.

## Renderer: `D3ChartRenderer` (lower level: `D3BaseRenderer`)

Below is a minimal bar chart that compiles and passes the compile gates as is. Write other charts in the same shape: build the scales and measure
the margin floor first, lay out with `layoutFrame`, then draw in `this.layer('chart')`. `MySnapshot` is the `z.infer` of the snapshot schema in
`definition.ts`; the config fields are under "Config fields" at the end.

```ts
// src/lib/my-chart-renderer.ts
import * as d3 from 'd3';
import { getColorScheme, themeColorCss } from '@vizchat/widget-sdk';
import {
  D3ChartRenderer,
  escapeTooltipText,
  formatChartValue,
  renderChartAxes,
  renderChartGrid,
  xAxisGutter,
  yAxisGutter,
  type D3RenderContext,
} from '@vizchat/widget-sdk/d3';
import type { MySnapshot } from '../definition';

type Item = MySnapshot['content']['items'][number]; // { id, label, value }

export class MyChartRenderer extends D3ChartRenderer<MySnapshot> {
  protected tooltipClass = 'my-chart-tooltip'; // omit it if you want no hover tooltip

  protected renderContent(snapshot: MySnapshot, context?: D3RenderContext): void {
    const { content, config } = snapshot;
    const items = content.items;
    const plot = this.layer('chart');

    // how wide the y ticks are depends on the data: build the scale first, measure the left-margin floor, then lay out
    const y = d3
      .scaleLinear()
      .domain([Math.min(0, d3.min(items, (d) => d.value) ?? 0), d3.max(items, (d) => d.value) ?? 0])
      .nice();
    // the title text is the node title (context.title); here you only decide whether and where to draw it
    const frame = this.layoutFrame(context, {
      showTitle: config.display.showTitle,
      titlePosition: config.display.titlePosition,
      empty: items.length === 0,
      emptyMessage: this.t?.('empty'), // viewState.empty in i18n
      plot,
      minLeft: yAxisGutter(y, Boolean(config.axes.yAxisLabel)),
      minBottom: xAxisGutter(Boolean(config.axes.xAxisLabel)),
    });
    if (frame.status !== 'ready') return;
    const { width, height } = frame.inner;

    y.range([height, 0]);
    const x = d3.scaleBand<string>().domain(items.map((d) => d.id)).range([0, width]).padding(0.3);
    if (config.display.showGrid) renderChartGrid(plot, { from: 'y', scale: y, crossExtent: width });
    renderChartAxes(plot, {
      width,
      height,
      xScale: x,
      yScale: y,
      margin: frame.margin,
      xAxisLabel: config.axes.xAxisLabel,
      yAxisLabel: config.axes.yAxisLabel,
    });
    // the x axis is keyed by id (labels may repeat); the ticks show the labels
    const labelOf = new Map(items.map((d) => [d.id, d.label]));
    plot.selectAll<SVGTextElement, string>('.tick text').text((id) => labelOf.get(id) ?? id);

    const [fill] = getColorScheme(config.appearance.colorScheme);
    plot
      .selectAll<SVGRectElement, Item>('rect.bar')
      .data(items, (d) => d.id)
      .join('rect')
      .attr('class', 'bar')
      .attr('x', (d) => x(d.id) ?? 0)
      .attr('width', x.bandwidth())
      .attr('y', (d) => y(Math.max(0, d.value)))
      .attr('height', (d) => Math.abs(y(d.value) - y(0)))
      .style('fill', themeColorCss(fill))
      .on('mouseover', (event: MouseEvent, d) =>
        this.tooltip.show(event, `${escapeTooltipText(d.label)}: ${formatChartValue(d.value)}`),
      )
      .on('mousemove', (event: MouseEvent) => this.tooltip.move(event))
      .on('mouseout', () => this.tooltip.hide());

    plot
      .selectAll<SVGTextElement, Item>('text.value')
      .data(items, (d) => d.id)
      .join('text')
      .attr('class', 'value')
      .attr('x', (d) => (x(d.id) ?? 0) + x.bandwidth() / 2)
      .attr('y', (d) => y(Math.max(0, d.value)) - this.typography.valueLabel.fontSize * 0.4)
      .attr('text-anchor', 'middle')
      .attr('font-size', `${this.typography.valueLabel.fontSize}px`)
      .attr('font-weight', this.typography.valueLabel.fontWeight)
      .style('fill', 'var(--vz-foreground)')
      .text((d) => formatChartValue(d.value));
  }
}
```

**The title is the node title**: its text comes from `context.title` (the `title` given to `canvas_createWidget`, also editable on the canvas), and
`layoutFrame` takes only `showTitle` / `titlePosition`. Don't add a title field to the schema or draw a title yourself — that creates a second
title that drifts apart from the node title.

Options of `layoutFrame(context, options)` (all but `empty` may be omitted):

| Option | Meaning |
| --- | --- |
| `empty` | Nothing to draw this frame: draws the empty state and returns `status: 'empty'` (required) |
| `emptyMessage` | Empty-state text, taken through `this.t?.(...)` |
| `showTitle` / `titlePosition` | Whether to draw the node title, and above or below (`'top'` / `'bottom'`); defaults: drawn, on top |
| `plot` | The plot group: moved to the top-left of the margins when given; leave it out when a legend must take its space before the margins are computed, and use only the returned `titleHeight` |
| `minLeft` | Floor of the left margin (px); pass `yAxisGutter(yScale, whether there is a y-axis title)`; when the categories sit on the left (horizontal bar chart), pass `categoryAxisGutter(category names, whether there is a y-axis title)` |
| `minBottom` | Floor of the bottom margin (px); pass `xAxisGutter(whether there is an x-axis title)` — margins are proportional, so in a short chart the x-axis title would sit on the ticks |
| `ratios` | Margins as fractions of the container, `{ top, right, bottom, left }` — **give all four**; the default suits most charts |

Return value: with `status: 'ready'` it has `inner` (plot width and height) and `margin`; `'cramped'` means the container can't fit a plot area — just skip the frame.

- Layers: `chartLayers` defaults to `['title', 'chart']`; each layer is a `<g class="<name>-group">`, emptied before every
  render. `{ name, parent: 'svg' }` hangs a layer on the svg root — when the main-container is translated as a whole (say, to
  a pie's center), layers laid out in screen coordinates such as the title and legend go there.
  A `{ name, retain: true }` layer is **kept across frames** and not emptied; you maintain it with a key join by id (you need this to
  animate data changes, see "Paint modes" below). Inside a layer, `this.sublayer(layer, name)` gives fixed child groups whose stacking
  order is set on the first frame, so marks added later never land on top of the axes.
- Without `D3ChartRenderer`, call `layoutChartFrame({ dimensions, container, titleGroup, title, empty, … })` on its own: it has no `context`,
  so pass the title text `context.title` explicitly.
- `this.t` is this render's translation function and also works in event callbacks; `this.tooltip.show(event, html)` /
  `move(event)` / `hide()`, wrapping every piece of data in the html in `escapeTooltipText(...)`. The tooltip is cleaned up
  when the renderer is destroyed.
- For extra setup, override `initializeRenderer` and call `super.initializeRenderer()` first; the same goes for
  `beforeRender(data, context)`.
- When the layer layout is unusual or you keep state across frames (a zoomable, pannable canvas), extend `D3BaseRenderer`
  directly and implement `initializeRenderer` / `renderContent` / `setupInteractions` yourself.
- Wrap every transition in `this.track(transition)`, or the thumbnail is captured mid-animation.

### Paint modes: entrance, data change, instant

The base class settles `this.paint` for every frame, so you never read the animation switch or the motion intent yourself:

| Mode | When | How to draw |
| --- | --- | --- |
| `enter` | First frame, and the chart appears during a walkthrough | Entrance animation |
| `update` | An op in a walkthrough changed the data (`addItems`, `updateItems`…) | Existing marks glide to their new place, new ones grow in, removed ones exit |
| `instant` | Everything else: drag-resizing, jumping pages, seeking, thumbnails, reduced motion, animation turned off, a structural change | Draw the final state in one step |

Override `animationEnabled(snapshot)` to return `config.display.enableAnimation` and the switch folds into the mode. How to write it:

- `this.motionApply(selection, (t) => t.attr(...), timing?)`: on `instant` it writes to the selection synchronously, otherwise it starts a transition and `track`s it for you.
  **Write existing elements all the way to their final state** (opacity 1 included): when two ops arrive in the same cue, an element that entered on the previous frame and is still waiting to fade in has its fade cancelled by the new transition.
- `this.motionExit(exitSelection, (t) => ...)`: removes the element once the exit has played; `this.motionText(selection, value, format)`: numbers roll from the old value to the new one.
- `this.motionLayout(...)`: layout attributes such as layer translation, overall scale and axes only transition on `update` frames (on entrance there is no previous position, and interpolating would fly the whole chart in from the origin).
  Pass `motion: (sel, apply) => this.motionLayout(sel, apply)` to `renderChartAxes` / `renderChartGrid` and the ticks glide to their new place.
- New items growing in one after another: `delay: (d) => enterDelay(rank, newCount)` — rank them by id among the new items; the callback's `i` is the index in the whole data.
- Morph the points of a line or curve with `polylineMorph(previousPoints, currentPoints)` (points carry a `key` and are matched by it).
- For config whose old and new layouts don't correspond (switching orientation, switching chart type), override `structuralKey(snapshot)` to return them joined into a string: when it changes, the frame is drawn instantly and retained layers are cleared and rebuilt.
- You can still gate the entrance animation with `this.shouldAnimateEntrance(config.display.enableAnimation)` (same as `paint === 'enter'`).
- For pictures where every middle frame must hold, such as mathematical plots, do not interpolate the drawn paths (the shape halfway between two curves is usually not a member of the family, and intersections drift off the curves):
  interpolate the inputs (parameters, free point coordinates) in the View with `useContentTween`, and hand each frame to the renderer to draw instantly in full; marks entering and leaving still fade with `motionExit` and friends.
  See [motion](motion.md).

## Font sizes and shared pieces

Don't hard-code SVG font sizes; read `this.typography.{axisLabel | valueLabel | legend | axisTitle | chartTitle | emptyState}`: the renderer base class works them out at the start of every render
from the canvas typography variables at the svg (`chartTypography(el)`, `@vizchat/widget-sdk`). Measurements taken before rendering (margins,
`yAxisGutter` and so on) are passed `this.typography` too. Grid and axis line widths use the canvas stroke tokens: `strokeCss('hairline' | 'axis' | 'series' | 'emphasis')`.

The shared pieces are all imported from `@vizchat/widget-sdk/d3` and callable on their own: `renderChartGrid`, `renderChartAxes` (on an ordinal axis with more categories than the labels fit, labels are thinned at even steps, always keeping the first; pass `xTickValues` to write every one; when the values are counts or other whole numbers, pass `integerTicks: { y: true }` (`x` for horizontal bars) so no tick reads “2.5 items”), `yAxisGutter` (how
wide the vertical-axis ticks and rotated title are, passed as the margins' `minLeft`; pass `this.typography` as the last argument), `categoryAxisGutter` (how wide the category names on the left are, also passed as `minLeft`), `xAxisGutter` (how tall the horizontal-axis ticks and title are, passed as `minBottom`), `computeChartLegendLayout` +
`renderChartLegend`, `renderChartNotice` (the chart is drawn but has something to say, such as data that couldn't be drawn),
`formatChartValue`. Series colors, `getColorScheme(scheme)`, don't depend on d3 and come from `@vizchat/widget-sdk`; the `theme` scheme is the document palette (the document theme's 8 derived categorical colors `chart-1…8`; it is the default for a chart's `colorScheme`) and gives theme references, so write them out with `themeColorCss`; to color by value, use the 7-step ramp from `getSequentialScheme()`.

When labels can cover each other (many data points, objects sharing an anchor), lay them out with `planLabelPlacement` from
`@vizchat/widget-sdk`: give each label a box and a `rank` (lower is placed first), use `aroundOffsets(gap)` for candidate positions,
and put helper text such as tick numbers in `yielding`. Mark labels that must show (the author asked for them, or the label is
the object's own content) `required`: they are placed first and `yielding` text gives way to them. Hide the labels the plan
returns as `hidden` and set `CROWDED_LABEL_ATTR` on them (`'required'` for required ones, which review reports) — never leave a
label in place on top of another.

Narration emphasis (`highlightOps` in `contract.md`): put `highlight: ItemHighlightSchema` in content and have the `highlightOps` apply
write it; after drawing the items, the renderer calls `applyItemEmphasis(selection, idOf, content.highlight, kind)` — `kind` is
`'shape'` (bars, slices: outlined in the emphasis colour) or `'line'` (lines: double width), and with `fade` the other items dim. It only
undoes the styles it wrote itself, so calling it on every redraw is fine.

## Config fields

Use the fragments from `@vizchat/widget-sdk` for a chart's common switches, so names, defaults and descriptions match the
platform's other charts:

```ts
appearance: z.object({ colorScheme: ColorSchemeSchema.default('default'), strokeStyle: strokeStyleField() }),
display: z.object({
  ...chartTitleFields(),                 // showTitle, titlePosition
  showGrid: chartGridField(),
  enableAnimation: chartAnimationField(),
}),
axes: z.object({ xAxisLabel: chartAxisLabelField('x'), yAxisLabel: chartAxisLabelField('y') }),
interaction: z.object({ enableTooltip: chartTooltipField() }).prefault({}),
```

**Put each fragment where it sits above** (`config.<group>.<field>`, registered in the SDK's `sharedFieldGroups`): the same field
sits in the same place in every widget, and a misplaced one fails compilation with `[shared-field-placement]`. When a default or
description doesn't fit, chain an override (`chartGridField().default(false)`, `.describe('…')`), or just
write the zod field by hand. The property-panel labels still go in the `config` section of the i18n files.
